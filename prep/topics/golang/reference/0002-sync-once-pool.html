sync.Once и sync.Pool — шпаргалка

Суть: Once отвечает «сделать ровно один раз» (корректность), Pool отвечает «не создавать заново временные объекты» (производительность, без гарантий).

sync.Oncesync.Pool
Гарантияровно один запуск, остальные ждутнет, GC чистит в любой момент
APIonce.Do(f)Get / Put, поле New
Кейсыленивый клиент БД, конфиг, регулярка; close(ch) один разbytes.Buffer в HTTP-обработчике, буферы декодирования, fasthttp
Не путатьс кэшем и с мьютексом на каждый вызовс кэшем и с пулом соединений

Правила Pool

  • Класть только пустые, легко пересоздаваемые объекты.
  • Reset после Get.
  • Не трогать объект после Put.
  • Мерить: go test -bench . -benchmem.

Нюансы Once (вне банка)

  • Паника в f считается выполненным вызовом, повтора не будет.
  • Долгая f блокирует всех остальных.
  • Go 1.21+: sync.OnceFunc, OnceValue, OnceValues.
once.Do(func() { db = open() })

buf := pool.Get().(*bytes.Buffer)
buf.Reset()
defer pool.Put(buf)
