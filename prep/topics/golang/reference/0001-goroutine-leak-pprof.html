Утечка горутин — шпаргалка

Суть: горутина заблокирована навсегда (канал без читателя или писателя, range по незакрытому каналу, вызов без таймаута), GC её не убирает. Симптом: число горутин и память растут и не падают. Находят через pprof goroutine-профиль, предотвращают через context и правила работы с каналами.

Причины

  • запись в канал, из которого никто не читает;
  • чтение из канала, в который никто не пишет;
  • for range ch без close(ch);
  • сетевой вызов без таймаута и context.

Как найти

ШагЧто
Заметитьruntime.NumGoroutine() или метрика go_goroutines растёт
Включитьimport _ "net/http/pprof" + http.ListenAndServe, не наружу
Сгруппировано/debug/pprof/goroutine?debug=1: стеки со счётчиком
Подробно?debug=2: каждая горутина, состояние, время ожидания
Сравнитьgo tool pprof -base a.pb.gz b.pb.gz: что выросло

Тысячи горутин на одной строке в ожидании — это утечка.

Как предотвратить

  • select с ctx.Done() в каждой точке ожидания, и на отправке тоже;
  • единственный результат: канал с буфером 1;
  • канал закрывает только отправитель; несколько отправителей: done или context;
  • таймаут на каждый внешний вызов;
  • defer cancel() после WithCancel/WithTimeout;
  • вне банка: errgroup / WaitGroup, тесты с goleak.VerifyNone(t).
select {
case ch <- v:
case <-ctx.Done():
}

Ловушки

  • «GC соберёт» — нет, горутина жива.
  • ctx.Done() проверяют только в начале, а блокируются позже.
  • Путают с утечкой памяти от срезов (topic_08).
  • pprof на проде открыт наружу.
