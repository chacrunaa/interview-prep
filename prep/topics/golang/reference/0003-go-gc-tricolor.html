Go GC — шпаргалка

Суть: конкурентный не поколенческий tricolor mark-and-sweep. От корней (стеки горутин, глобальные переменные) по указателям красит достижимое, остальное (белое) чистит в фоне. Мусор это недостижимое, а не ненужное.

Цвета

  • Белый — не проверен; после маркировки мусор.
  • Серый — найден, ссылки не обработаны.
  • Чёрный — найден, ссылки обработаны.

Фазы

  1. Sweep Termination (STW, коротко)
  2. Mark (параллельно, Write Barrier включён)
  3. Mark Termination (STW, коротко)
  4. Sweep (параллельно, Write Barrier выключен)

Ключевое

ЧтоЗачем
Write Barrierне дать спрятать живой объект в чёрный; помечает серым; небольшой оверхед только в Mark
Non-generationalсканирует всё; выручает escape analysis (стек)
GOGC=100старт сборки при росте кучи вдвое от живых данных; выше значит реже, но больше памяти
GOMEMLIMIT (1.19+)мягкий лимит; GC чаще; защита от OOM в контейнере
GOGC=offвыключить; только для коротких утилит

Алгоритм сменить нельзя. Диагностика (вне банка): GODEBUG=gctrace=1, -benchmem, -gcflags="-m".

Ловушки

  • «Находит ненужное» — нет, недостижимое.
  • «Останавливает всю программу» — только две короткие STW.
  • Срез от большого массива держит весь массив: делать copy.
  • Рост кучи до порога GOGC не утечка; утечка это рост живых данных после GC.
