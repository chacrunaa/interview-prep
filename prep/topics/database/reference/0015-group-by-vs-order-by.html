GROUP BY и ORDER BY — шпаргалка

Суть: меняется число строк — GROUP BY (схлопывает в группы). Не меняется, только порядок — ORDER BY. GROUP BY порядок не гарантирует.

Сравнение

GROUP BYORDER BY
Строкодна на группустолько же
Зачемагрегаты по группепорядок, топ-N, пагинация
В SELECTколонки группировки + агрегаты (или всё при группировке по PK)что угодно
Алиасы из SELECTпо стандарту нет (PostgreSQL разрешает)да

Порядок выполнения

FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

  • WHERE — фильтр строк, агрегатов и алиасов ещё нет.
  • HAVING — фильтр групп, агрегаты есть.
  • ORDER BY — алиасы есть; после GROUP BY только группируемые колонки и агрегаты.

Шаблоны

-- топ-N
SELECT customer, sum(amount) AS total
FROM sales GROUP BY customer
HAVING sum(amount) > 2000
ORDER BY total DESC LIMIT 2;

-- стабильная пагинация
ORDER BY created_at, id

-- NULL явно
ORDER BY category NULLS LAST

Ловушки

  • «GROUP BY сортирует» — нет (миф из MySQL 5.x). В плане HashAggregate — порядок любой.
  • column must appear in the GROUP BY clause — колонка не в группировке и не в агрегате.
  • Агрегат в WHERE — ошибка, нужен HAVING.
  • Одинаковые значения в ORDER BY — порядок между ними не определён → тай-брейк id.
  • NULL: в GROUP BY одна группа; в ORDER BY PostgreSQL считает их наибольшими (в конце при ASC).
  • В Go результат в слайс, не в map — иначе порядок пропадёт.
Формулировка для собеса: «GROUP BY схлопывает строки в группы ради агрегатов, в SELECT — только колонки группировки и агрегаты. ORDER BY число строк не меняет, выполняется почти последним, поэтому видит алиасы. GROUP BY порядок не гарантирует — нужен ORDER BY, для пагинации с уникальным тай-брейком. Строки фильтрует WHERE, группы — HAVING.»
