Нормализация — шпаргалка

Роль нормализации: разложить один "файл на всё" по таблицам так, чтобы каждый факт хранился один раз — тогда изменение факта не может рассинхронизироваться.

ФормаУсловиеЧинит
1NFЯчейки атомарны, нет списков в одном полеНеделимость данных
2NF1NF + поле зависит от всего составного ключаЧастичную зависимость от части ключа
3NF2NF + нет зависимостей через другое неключевое полеТранзитивную зависимость
BCNFУсиленная 3NF: слева от X → Y всегда суперключРедкие edge-case зависимости
АномалияСуть
InsertНельзя добавить факт без связанного факта (клиента без заказа)
UpdateФакт продублирован — обновили не везде, данные разъехались
DeleteУдалили одно — случайно стёрли и логически не связанное другое
Денормализация (author_name в comments, likes_count вместо COUNT(*)) — не ошибка, а осознанный компромисс "скорость чтения вместо чистоты схемы" в высоконагруженных системах.
