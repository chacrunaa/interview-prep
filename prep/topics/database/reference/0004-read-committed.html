Read Committed — шпаргалка

Суть: читаешь только зафиксированное. Грязного чтения нет, но между двумя запросами в одной транзакции данные могут поменяться.

АномалияНа Read Committed
Грязное чтениезащищено
Неповторяющееся чтениевозможно
Фантомное чтениевозможно
Потерянное обновление (read-modify-write в коде)возможно

Два способа реализации

БлокировкиMVCC
Какчитатель ставит shared-блокировку, писатель ждёт; писатель блокирует строки для читателейкаждое изменение создаёт новую версию строки; читатель получает последнюю зафиксированную
Плюсмало памятичитатели и писатели не мешают друг другу, быстрее
Минусожидания, deadlockпамять под версии, уборка (VACUUM / undo-логи)

Конкурентная запись в одну строку

Уровень (PostgreSQL)Что делает вторая транзакция
Read Committedждёт первую; после её коммита перечитывает строку и применяет свой UPDATE. Ошибки нет
Repeatable Read / Serializableпосле коммита первой получает ошибку could not serialize access due to concurrent update, нужен повтор транзакции

Правило «первый коммит побеждает, остальные откатываются с ошибкой» из общих учебников — это поведение снимка на Repeatable Read, а не Read Committed.

Как не потерять обновление на Read Committed

UPDATE accounts SET balance = balance + 20 WHERE id = 1;       -- считаем в БД
SELECT balance FROM accounts WHERE id = 1 FOR UPDATE;           -- или блокируем строку

Факты для собеса

  • Read Committed — уровень по умолчанию в PostgreSQL. В MySQL InnoDB по умолчанию Repeatable Read.
  • В PostgreSQL на Read Committed каждый запрос видит свой снимок; на Repeatable Read снимок один на всю транзакцию.
  • MVCC не отменяет блокировки записи: две записи в одну строку всё равно ждут друг друга.
Формулировка для собеса: «Read Committed гарантирует чтение только зафиксированных данных, то есть грязного чтения нет. Между двумя запросами в транзакции другая может закоммититься, поэтому возможны неповторяющееся чтение и фантомы. Реализуется блокировками или MVCC: при MVCC читатель берёт последнюю зафиксированную версию и не блокирует писателей, а платим памятью под версии.»
