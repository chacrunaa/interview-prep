SQL и NoSQL — шпаргалка

Суть: NoSQL — не одна технология, а четыре модели данных без реляционной. SQL проектируют «от данных» (нормализация, JOIN, ACID), NoSQL «от запросов» (денормализация, гибкая схема, горизонтальное масштабирование). Дефолт: PostgreSQL, NoSQL — по конкретной причине.

Четыре вида NoSQL

ТипПримерКогда
Key-ValueRedisКэш, сессии, счётчики, TTL
ДокументнаяMongoDBОбъект с вложенностью, читается целиком
Wide-columnCassandra, HBaseОгромная распределённая запись, чтение по ключу
ГрафоваяNeo4jСвязи и обход (друзья, рекомендации)

«Колоночные» бывают двух семейств: wide-column (Cassandra) и аналитические (ClickHouse), см. урок 0007.

SQL против NoSQL

SQLNoSQL
СхемаФиксированнаяГибкая (живёт в коде)
СвязиFK, JOINВложение, денормализация
ЗапросыЛюбые, SQLПод заранее известные паттерны
ТранзакцииACIDЗависит от базы (Mongo 4.0+, Redis MULTI/EXEC)
КонсистентностьСильнаяЧасто eventual или настраиваемая
МасштабированиеВертикально, шардинг сложнееГоризонтально «из коробки»

CAP

C — все видят одно и то же, A — каждый запрос получает ответ, P — переживает разрыв сети. По банку «два из трёх»; точнее: разрыв неизбежен, выбор C или A в момент разрыва (вне банка).

Ловушки

  • «NoSQL быстрее и современнее» — нет, другие компромиссы.
  • «В NoSQL нет транзакций» — есть, но зависят от базы.
  • «SQL не масштабируется» — масштабируется, но сложнее.
  • «Схемы нет» — она переехала в код.
  • Не уточнить тип NoSQL.
