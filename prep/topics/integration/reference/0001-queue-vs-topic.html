Очередь и топик — шпаргалка

Суть: очередь (RabbitMQ) — раздача работы: прочитали и подтвердили — сообщение удалено. Топик (Kafka) — журнал событий: чтение его не удаляет, у каждого читателя своя закладка (offset).

Запись

  • RabbitMQ: продюсер → Exchange (+ routing_key) → привязки → 0..N очередей. В очередь напрямую не пишут. Надёжность: Publisher Confirms.
  • Kafka: продюсер → топик → партиция по hash(key) % N (без ключа — round-robin) → дописывается в конец, получает offset. Надёжность: acks, репликация, идемпотентность.

Чтение

RabbitMQ (очередь)Kafka (топик)
МодельPush, ограничение prefetchPull, poll()
После чтенияACK → удаленоcommit offset → осталось до retention
Кто двигает местоБрокерКонсьюмер
Воркеры сервисаДелят очередь, без лимитаДелят партиции, не больше их числа
Несколько сервисов на событиеОчередь на каждого (fanout)Consumer group на каждого
ReplayНетДа, пока не истёк retention
ПорядокОдна очередь + один консьюмерВнутри партиции (ключ)
СкоростьДесятки тысяч/с на узелМиллионы/с на кластер

Выбор

  • RabbitMQ: фоновые задачи (письма, PDF, биллинг), сложная маршрутизация, приоритеты, RPC.
  • Kafka: логи, метрики, кликстрим, Event Sourcing, один поток для многих независимых читателей, replay.

Ловушки

  • «Kafka — это быстрая очередь» — нет, это лог с offset'ами.
  • commit в Kafka не удаляет сообщение, удаляет только retention.
  • Консьюмеров в группе больше, чем партиций — лишние простаивают.
  • «Порядок гарантирован» — только внутри партиции.
  • «Topic» в RabbitMQ — это тип обменника с маской (*, #), а не журнал Kafka.
