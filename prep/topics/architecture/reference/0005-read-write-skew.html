Главное

Read / write ratio — чтений к записям за одно время, в одних единицах. Перекос — ключевое требование (ASR): от него идут хранилище, кеш, очереди.

Курс: считаем по требованиям

Проект 2

  • Запись: ~28 000 точек/с (пик ~50 000), ~2,4 млрд/сутки. Чтение: API ~600 RPS на пике, но тяжёлые (fan-out ___).
  • 28 000 : 600 — разные единицы, так не делить. По строкам: ___ записи против ___ чтения.
  • Первым упёрлась запись: «Too many parts» → батчи и буферизация. ClickHouse, брокер, отдельный синхронный API.

Ответ вслух

«Write-heavy по потоку: ~28 тысяч точек/с, пик 50 тысяч. Чтений ~600 RPS, но каждое тяжёлое. Дизайн шёл от записи: ClickHouse, брокер, батчи — первым упёрлось «Too many parts» на мелких вставках».

Ловушки

  • Делить точки на HTTP-запросы.
  • Назвать перекос без следствий для дизайна.
  • Путать число чтений и их стоимость.
  • Лечить запись кешем, держать много индексов на write-heavy таблице.
