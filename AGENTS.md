# interview-prep

Личный репозиторий для активного поиска работы Go-разработчиком. Два глобально зарегистрированных скилла (симлинки в `~/.Codex/skills/`):

- **`career`** (`skills/career/`) - конвейер откликов: `new` (вакансия → резюме, письмо), `answers` (вопросы HR-форм и ботов), `status` (стадии, архив).
- **`teach-go`** (`skills/teach-go/`) - подготовка: `lesson`, `drill`, `mock`, `review`, `status` и `live qa|code` - живая помощь на созвоне. Кастомизация базового `teach` (`~/.agents/skills/teach`).

## Структура

```
me/          личное: правда, постоянное        - мастер-резюме, facts.md
fish/        рыба: досочинённое, безликое      - story, bullets, patterns, answers, archive
pipeline/    конвейер вакансий                 - BOARD.md, inbox.md, YYYY-MM-<slug>/, archive/
prep/        данные teach-go                   - MISSION, progress, уроки
reference/   чужое, только для чтения          - warriors/ + разбор
rules/       общий стиль текста от первого лица
skills/      career, teach-go
```

## Инварианты

- **`me/` и `fish/` не пересекаются.**
  - В `me/` нет ни одного досочинённого факта. Скиллы его только читают, меняет пользователь или Codex по прямой просьбе.
  - В `fish/` нет ни названий компаний, ни личных данных (имя, контакты): места работы обозначаются слотами `[S1]`-`[S3]`, `[S0]`. Соответствие слот → компания записано только в `me/facts.md`.
  - Стороны встречаются только в `pipeline/<вакансия>/`.
- **`me/cv-en.txt` и `me/cv-ru.md` - мастер-резюме** с реальными контактами. Инструменты их никогда не перезаписывают.
- **`fish/story.md` - одна привязка рыбы к месту работы на все версии.** Сначала запись в story, потом использование.
- **Одна вакансия - одна папка** `pipeline/YYYY-MM-<slug>/` с `card.md` (исходный текст вакансии, разбор, какая рыба ушла, история). Закрытые вакансии переезжают в `pipeline/archive/`.
- **`pipeline/BOARD.md` - единая точка обзора.** Обновляется в конце каждого режима `career`.
- Ни один скилл не пишет в `~/personal/InterviewPro` (внешний банк вопросов, только чтение) и в другие репозитории.

Репозиторий содержит реальные личные данные (контакты в `me/`). При работе с внешними сервисами или публикацией это учитывается.
