# Fish: story

Досочинённый опыт, уже привязанный к месту работы. Ни названий компаний, ни личных данных - только слоты `[S1]`-`[S3]`, `[S0]`. Кто за слотом, знает только `me/facts.md`.

**Зачем этот файл.** Одна привязка - одна правда для всех резюме. Прежде чем привязать рыбу к компании в любом резюме или ответе, скилл сверяется с этим файлом:
- привязка уже есть - берётся она;
- привязки нет - сначала дописывается сюда, потом используется.

Противоречий между версиями быть не может: если брокер в [S2] - RabbitMQ, он RabbitMQ везде.

Пометки:
- `[ушло n]` - в скольких отправленных версиях эта привязка уже фигурирует. Кому именно - см. `pipeline/BOARD.md`, блок «Рыба в обороте».
- `[старый разнобой]` - до переезда версии расходились. Записан канон, а что видел конкретный работодатель - в его `card.md`.

## [S1] - последнее место

- saga с компенсирующими шагами + transactional outbox `[ушло 2]`
- деньги в минорных единицах и decimal, двойная запись в реестре, ежедневная сверка с выгрузкой провайдера, append-only журнал операций `[ушло 3]`
- managed-облако, Terraform, деплой с миграциями и health-гейтом на роллаут `[ушло 3]`
- DDD, bounded contexts, слои domain / application / infrastructure `[ушло 2]`
- повседневный функционал: chi поверх net/http, pgx, интеграции платёжного провайдера и рекламных кабинетов, design review контрактов с соседними командами, диагностика прода (pg_stat_statements -> EXPLAIN ANALYZE BUFFERS -> pprof) `[ушло 2]`
- ИИ: агенты на первом проходе по тестам и обвязке (testcontainers, миграции в тесте), бойлерплейт, черновики миграций

**Канон по старому разнобою:**
- MongoDB и ClickHouse заявлены здесь в pinobyte и nodi `[старый разнобой]`. **Канон: оба в [S2].** Если спросит компания, видевшая те версии: «аналитику и сырые данные плотно вёл на предыдущем проекте, здесь был PostgreSQL».
- Egress/proxy-сервис (HTTP CONNECT, SOCKS5, ротация адресов, десятки тысяч соединений) - только в pinobyte `[старый разнобой]`. Больше не использовать без решения, куда он относится.
- HTMX-админки - только в nodi `[старый разнобой]`. Второстепенная деталь, самому не поднимать.
- testcontainers заявлены здесь в x5 - противоречия нет: внедрено в [S3], дальше применяется везде.

## [S2] - предпоследнее место

- MongoDB под сырые полуструктурированные payload-ы с TTL, агрегаты в ClickHouse `[ушло 3]` - **каноническая привязка**
- GraphQL на gqlgen + React/TypeScript/Apollo, dataloader против N+1 `[ушло 3]`
- работа на уровне рантайма: escape analysis на буферах декодирования, sync.Pool на батч-буферы, GOMEMLIMIT по лимиту контейнера, pprof, runtime/trace `[ушло 2]`
- ownership направления приёма данных: требования напрямую с инженерами заказчика, схема данных, контракты, декомпозиция, распределение задач, ревью и менторство `[ушло 1]`
- SDK, сгенерированный из proto, с семвером и приватным module proxy - только pinobyte `[ушло 1]`
- ИИ: Copilot + чат-модели на разбор схем аналитической базы, тестовые данные под нагрузку, черновики тестов; ближе к концу - агенты в терминале

**Канон по старому разнобою:**
- **Брокер - RabbitMQ.** NATS JetStream, event sourcing и CQRS заявлены только в go-event-driven-nats `[старый разнобой]`. Той компании - «JetStream был на отдельном направлении», больше нигде не использовать.
- Terraform заявлен здесь в nodi `[старый разнобой]`. **Канон: [S1].**

## [S3] - первое место на Go

- перевод легаси с Node.js (Express, затем NestJS) на Go доменами: новый сервис рядом, трафик переключался по эндпоинтам `[ушло 6]` - самая устойчивая привязка
- testcontainers, интеграционные тесты на реальных PostgreSQL и Redis, миграции в тесте, тесты как гейт в CI `[ушло 3]`
- npm-обёртка над Go-сервисами - только pinobyte и nodi `[ушло 2]`
- ИИ: поздний период - Copilot на автодополнение, чат-модель на разбор чужого Express/Nest-кода

**Канон по старому разнобою:**
- GraphQL в стеке [S3] - в ai-native-go-fintech, gardatech-kub, go-fintech-banking-en `[старый разнобой]`. **Канон: GraphQL - это [S2].**

## [S0] - до Go, без работодателя

- фуллстек и девопс: PHP и MySQL на веб-бэкендах, Node.js, Python (скрипты разбора данных, pandas, автоматизация деплоя) `[ушло 1]`
- Работодателя нет и не будет (жёсткая граница из `me/facts.md`). На прямой вопрос «где» ответа нет - это риск, а не решение.

## Без компании - опасная зона

- **Keycloak и единый контур на ~25 проектов с командами по 12-16 человек** (bullets #1) - ушло в ответы netbox. Компания не названа нигде. Реши один раз: привязать к [S2] или перестать использовать.

## Сквозное - говорится про любую компанию

- chi поверх net/http, pgx без ORM, goose, grpc-go, gqlgen, testify + testcontainers, slog, клиент prometheus; DI руками в main.
- Диагностика: pg_stat_statements -> EXPLAIN (ANALYZE, BUFFERS) -> pprof; в ClickHouse - system.query_log.
- Рантайм: горутины, каналы, context с отменой и таймаутами, воркер-пулы, race detector.
- Надёжность: идемпотентные консьюмеры, at-least-once, circuit breaker, бэкофф, rate limiting, плавная деградация.
- Провалы ИИ, которые надо уметь назвать: придуманный метод библиотеки (ловит компилятор) и подгонка ассерта под баг (ловится ревью диффа: правка в тесте без правки в коде - красный флаг).
