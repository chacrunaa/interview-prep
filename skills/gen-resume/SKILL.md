Ты собираешь одно резюме под одну вакансию. Не пишешь с нуля: берёшь эталон, подбираешь рыбу по тегам, привязываешь к местам работы через `story.md`, прогоняешь проверки. Результат повторяем: два прогона на одной вакансии дают один и тот же состав буллетов.

`CT` = `~/personal/interview-prep`. `D` - направление, `P` = `CT/<D>/pipeline/<slug>/`. Инварианты репозитория (`CT/CLAUDE.md`) действуют целиком: направления изолированы, `me/` только читается, в `fish/` нет компаний и личных данных, единственная константа - стек Go / JS.

Вакансия приходит через `CT/<D>/inbox.md`, как в `career`: пользователь вставляет сырой текст, скилл обрабатывает и очищает файл. `scan.md`, Hirify MCP и любые другие источники скилл не читает и от них не зависит.

## Вход и язык

- **Источник - `CT/<D>/inbox.md`**: всё ниже разделителя `---` считается текстом вакансии (можно со ссылкой, названием компании и пометками пользователя). Пусто - спроси одним вопросом, где вакансия, и остановись.
- `slug` необязателен: нет - выведи из компании и сути роли (`латиница-через-дефис`), как в `career`. Папка `P` = `CT/<D>/pipeline/YYYY-MM-<slug>/`.
- Папки нет - создай её и `card.md` (формат `skills/career/FORMATS.md`) с исходным текстом вакансии целиком, затем очисти `inbox.md` до шапки. Ничего не теряется.
- Папка есть, а `inbox.md` пуст - это пересборка: текст вакансии берётся из её `card.md`. Папка есть и `inbox.md` не пуст - спроси, это та же вакансия (обновить текст) или новая.
- Разбор вакансии (пересечения компаний, стоп-условия) делает сам скилл, шаг 0 ниже; отдельный `/career new` не нужен.
- Язык: аргумент, иначе язык текста вакансии. Для `hirify` вакансия на en - резюме на английском (R-160), даже если эталон русский: факты те же, перевод делаешь сам.
- Режим: `compact` по умолчанию (канон, раздел 2 ниже). `extended` (блоки «Команда / Функционал / Результаты / ИИ в работе») - только если пользователь просит или вакансия от аутстаффа / просит расписать задачи; в логе он появился 2026-09-29 по прямому запросу.

## Что читать (всегда заново)

1. Текст вакансии (из `inbox.md` или `P/card.md`), гипотеза и история отправок из `P/card.md`, если он есть.
2. `CT/<D>/CANON.md` и `CT/<D>/master/` - правила и эталон. Эталон - скелет и источник фактов и цифр. Пустой `CANON.md` (сейчас `hirify`) - берёшь `CT/reference/roast-analysis/canon-<D>.md` (ярусы «Красавчик» и «консенсус») и раздел 2 ниже.
3. `CT/me/facts.md` - слоты → компании, команды, открытые вопросы. `CT/me/cv-*.txt` - только контакты и справка.
4. `CT/<D>/fish/story.md`, затем `patterns.md`, `bullets.md`. `archive.md` не читать.
5. [LESSONS.md](./LESSONS.md) - что уже стрелило в прогонах. [CHECKLIST.md](./CHECKLIST.md) - финальные проверки.
6. Первый-лицо-текст (summary) - по `CT/skills/career/WRITING-STYLE.md`: только дефис, без «ё», «го» не «Go» в разговорных фразах (в резюме технологии как есть: Go).

## Алгоритм

### 0. Стоп-условия, до подгонки

- Локация / гражданство / часовой пояс из вакансии не совпадают с профилем пользователя - сказать и остановиться: рыбой это не снимается (nodi, LESSONS #1).
- Стек вакансии не Go / JS - сказать до подгонки. Java / Spring не заявлять никогда, заходить через Go-ветку требования.
- Компания уже есть в `CT/*/pipeline/**/card.md` (все три направления) - назвать, какая версия ушла, и сверить факты (LESSONS #5).
- Расхождение названий компаний между `master/` и `me/facts.md` по одному слоту - стоп и вопрос пользователю. Сам не выбираешь.

### 1. Профиль вакансии

Выпиши в `card.md` (раздел «Разбор») машинно, а не прозой:
- `must`: требования, без которых не пройдёшь (стек, годы, домен);
- `nice`: пожелания;
- теги осей: домен, тип бизнеса, тип системы, тип компании (оси из `skills/career/FORMATS.md`);
- `gaps`: что из `must` не закрыто мастером, и чем закрываешь (рыба, близкий опыт, смежная формулировка).

### 2. Бюджет (канон, `reference/roast-analysis/volume.md`, `warriors-analysis.md`)

| Секция | compact |
|---|---|
| Всего | 450-700 слов, 2 страницы; эталон-мастер длиннее, это не норма |
| Шапка | тайтл с грейдом Senior и языком, годы и одна метрика на виду; контакты как в мастере |
| О себе | 50-80 слов, без «я», 3-4 числа или факта, без эссе |
| Опыт | 3 места подробно; буллетов 5 / 4 / 3 (последнее / предпоследнее / первое); в `extended` - 6-9 |
| Буллет | глагол + что + как (1-2 техники) + число (до → после или масштаб); 2-3 числа на место, не в каждом |
| Под местом | одна строка стека и одна строка о компании с масштабом |
| Навыки | 7-8 строк «Категория: список», без пояснений в скобках; каждый навык есть в опыте, основной первым; поверхностное - «working knowledge» |
| ИИ | одна строка в навыках + один буллет; больше - только для AI-native вакансии |

### 3. Подбор рыбы

Источники по приоритету: `master/` → `me/facts.md` → `story.md` → `patterns.md` → `bullets.md` → новое.

Счёт буллета: `+3` за пересечение с `must`-тегами, `+1` с `nice`, `+1` за совпадение домена / типа системы, `-1` за `used` ≥ 3 в вакансиях того же домена (рыба не должна протираться), `-3` за любой пункт из `LESSONS`-блока «не использовать». Берёшь верх по счёту в пределах бюджета слота. Один тег / одна тема - один буллет (без дублей «обязанность + результат»).

Новое досочиняешь по правилу уверенности из `career`: сначала привязка в `story.md` под слот, потом использование, потом запись в `bullets.md`; 2+ пересекающихся записи без паттерна - новый паттерн. Число в буллете - только реальное (мастер, `facts.md`, `story.md`) или явно оговорённое пользователем. Нет числа - формулируй без него, `[N]` в тексте не оставлять. Абсолютные цифры (100%) - только с понятным способом измерения (LESSONS #3).

### 4. Привязка к слотам

- Брокер, хранилища, облако, библиотеки берутся из `story.md` для слота. Противоречить нельзя: если Mongo в `[S2]`, она в `[S2]` везде.
- Годы, должности, периоды можно менять под гипотезу, но каждое отступление от `master/` и `me/` записывается одной строкой в «Гипотезу» `card.md`.
- Должность в тексте и тайтл в шапке не должны вопиюще расходиться (Senior в шапке при «Go-разработчик» везде - вопрос на собесе, LESSONS #4): либо привести к форме «Backend Engineer (Go)», либо записать в риски.

### 5. Сборка и подстановка

Каркас: шапка → о себе → опыт (последнее место первым) → навыки → образование / языки. Слоты `[S1]..[S3]` заменяются названиями из мастера / `me/facts.md`, контакты из мастера. Файл: `P/cv-en.txt` или `P/cv-ru.txt`. Существующий файл не затирай молча: старый переименуй в `cv-<lang>.prev.txt`.

Формат буллета и порядок секций - один на все резюме направления. Ориентиры формы: `reference/warriors/` и разбор `reference/warriors-analysis.md` (структура, объём, формула; числа и легенды оттуда не брать).

### 6. Проверки

Прогон [CHECKLIST.md](./CHECKLIST.md) построчно. Любой красный пункт - исправить и перепроверить, а не пропустить. Что нельзя исправить сам - строка в «Риски» `card.md` и в ответ пользователю.

### 7. Учёт (как в `career`)

- `P/card.md`: язык, режим, гипотеза (одна строка), состав рыбы (номера `b` / `p` и привязки `story`), риски, история.
- `CT/<D>/fish/*`: `used` у использованных записей +1; `story.md`: `[ушло n]` +1 у использованных привязок.
- `CT/<D>/pipeline/BOARD.md` - строка вакансии и блок «Рыба в обороте».
- `CT/audit/vacancy-history.md` - строка в конец (append-only), `CT/audit/TLDR.md` - автоматические разделы; «Заметки» только дописывать.

## В конце ответа

Скажи: сколько буллетов взято из мастера / переиспользовано / новых, сколько слов и страниц, какие стоп-флаги и риски остались, что должен проверить сам пользователь (досочинённое).
