# Форматы файлов career

Пути `me/` - относительно `CT` (`~/personal/interview-prep`). Все остальные (`fish/`, `inbox.md`, `pipeline/`) - внутри направления `CT/<D>/`, где `D` = `hh` | `hirify` | `linkedin`. Раскладка у всех трёх одинаковая.

Расширение показывает формат: `.md` - служебные файлы, которые читаются в редакторе; `.txt` - готовые тексты для копирования работодателю (резюме, письмо, ответы).

---

## me/ - личное

Формат свободный, файлы ведёт пользователь. Скилл только читает. Единственное требование к `me/facts.md` - таблица «Места работы и слоты» (слот → компания → период → должность): по ней слоты в рыбе заменяются реальными названиями.

---

## fish/bullets.md

Вверху - индекс по тегам (обновляется при каждой правке), ниже записи. Номер записи никогда не переиспользуется.

```md
## #тема #тема #домен #тип-бизнеса #тип-системы #тип-компании
<!-- id: 28 | added: 2026-10-02 | source: <slug>-new | used: 1x (<slug>) -->
{буллет: эффект + что делал + стек. Без названий компаний и личных данных}
```

Оси тегов (открытые списки):
- домен: `#adtech #iot #fintech #crypto #ai #security #ecommerce #retail #igaming #healthtech #logistics #telecom #network-infra` ...
- тип бизнеса: `#b2b #b2c #b2b2c #b2g #marketplace #internal-tools`
- тип системы: `#saas #crm #billing #payment-gateway #data-platform #ad-platform #identity-platform #proxy-network #ecommerce-platform` ...
- тип компании: `#bigtech #startup-early #startup-growth #scaleup #avg-product #enterprise #outsource #bootstrapped`

**Кап 50.** При 51-й записи вытесняется запись с наименьшим `used` (при равенстве - самая старая) в `fish/archive.md`.

## fish/patterns.md

Обобщение на пересечении 2+ записей `bullets.md` с общими тегами. Формат тот же, плюс `[pattern]` в заголовке и `derived-from`:

```md
## #fintech #b2b #payments [pattern]
<!-- id: 10 | added: 2026-10-02 | derived-from: bullets #14, #17 | used: 0x -->
{обобщённая форма задачи и решения}
```

**Кап 30**, вытеснение как у `bullets.md`.

## fish/archive.md

Append-only. Запись переносится как есть, в метаданные добавляется `archived: <дата> | из: bullets|patterns`. Ни один режим не читает этот файл автоматически.

## fish/story.md

Разделы по слотам: `## [S1] - последнее место`, `## [S2] ...`, `## [S3] ...`, `## [S0] ...`, плюс «Без компании - опасная зона» и «Сквозное». Одна строка - одна привязка:

```md
- MongoDB под сырые payload-ы с TTL, агрегаты в ClickHouse `[ушло 3]` (bullets #6)
```

`[ушло n]` увеличивается, когда привязка уходит в новую вакансию. Если старые версии расходились, в разделе слота есть подпункт «Канон по старому разнобою».

## fish/answers.md

Пары вопрос-ответ, пары разделяются пустой строкой. Компании - слотами.

```
> {вопрос дословно}
{ответ, "на [S2] ..." }
```

## inbox.md

Шапка с пояснением, ниже разделитель `---` и сырой ввод пользователя: текст вакансии или вопросы формы (по одному на строку, можно с `-`). После обработки всё ниже `---` удаляется.

## scan.md - только у направлений с MCP (сейчас `hirify`)

Лента триажа. Перезаписывается целиком каждым прогоном `scan`. Вакансии отсюда уходят в `new` по `vacancy_id`.

```md
# Scan · <D>

Прогон: YYYY-MM-DD | фиды: <id>, <id> | карточек просмотрено: N | прочитано: M | квота после прогона: read M/1000, reveal 0/100, apply 0/100

## Шортлист

| # | Вакансия | id | Компания | Стек из карточки | $/мес | Язык | Отклик | Рыба закрывает | Не закрыто |
|---|---|---|---|---|---|---|---|---|---|
| 1 | [Senior Go ...](url) | 1176241 | ... | go, kafka, nats | 2900 | en | apply | b8 b11 p3 | GraphQL |

## Отсеяно по карточкам, без чтения

- не Go/JS: N (кратко, какие)
- РФ по `regions`/`macroregion`: N
- грейд: N
- уже отправлено (`has_applied`/`in_tracker`): N

## Уже отправлено

| Компания | Как | Дата | Стадия по Hirify | Папка в pipeline |
|---|---|---|---|---|

## Спросить

- расхождение или решение, которое остаётся за пользователем
```

Колонка «Отклик»: `apply`, если в карточке `can_apply_directly: true`, иначе `reveal`. Сам режим ни то, ни другое не выполняет. `$/мес` - `salary.salary_in_usd` из карточки, чтобы валюты были сравнимы. «Рыба закрывает» - совпадения по тегам с `fish/bullets.md` и `fish/patterns.md`, без траты рыбы: записи не создаются и счётчик `used` не растёт.

## pipeline/YYYY-MM-<slug>/card.md

```md
# <slug>

| | |
|---|---|
| Компания | ... |
| Роль | ... |
| Источник | hh / реферал / Hirify / LinkedIn / бот ... |
| Гипотеза | что проверяет этот отклик, одной строкой: «8 лет вместо 5», «локация Лимасол», «тайтл Senior» |
| Подготовлено | YYYY-MM-DD |
| Отправлено | YYYY-MM-DD или ? |
| Стадия | черновик / отклик / ... |
| Дальше | что и когда |

## Файлы
- [cv-en.txt](cv-en.txt)

## Вакансия
{исходный текст целиком}

## Разбор
- Домен / Тип бизнеса / Тип системы / Тип компании: #теги
- Что в вакансии есть, а в мастере слабо: ... -> чем закрыто
- Что не закрыто вообще: ...

## Рыба, ушедшая сюда
- новая: bullets #28, patterns #10
- переиспользованная: bullets #6, #7; story [S2] MongoDB

## История
- YYYY-MM-DD - черновик
- YYYY-MM-DD - отклик
```

## pipeline/YYYY-MM-<slug>/cv-en.txt | cv-ru.txt

Готовое резюме с реальными названиями компаний и контактами из мастера. Формат по умолчанию - как в мастере (`me/cv-en.txt`).

## pipeline/YYYY-MM-<slug>/letter.txt

Сопроводительное, простой текст.

## pipeline/YYYY-MM-<slug>/answers.txt

Снапшот всего батча формы в формате `fish/answers.md`, но с реальными названиями компаний. Повторный прогон с тем же `slug` перезаписывает файл.

## pipeline/BOARD.md

Перегенерируется целиком в конце каждого режима:

```md
# Board · <D>

Обновлено: YYYY-MM-DD

**В работе: N · в архиве: M · ближайшее: <что и когда>**

## В работе
| Вакансия | Готово | Стадия | Гипотеза | Файлы | Рыба | Дальше |
(ссылка на card.md; самые свежие сверху)

## Архив
| Вакансия | Итог | Когда | Почему |

## Рыба в обороте
| Рыба | Суть | Ушло | Куда |
(по убыванию "ушло"; b = bullets, p = patterns)
```

## audit/vacancy-history.md

Append-only лог всех прогонов `career` по всем направлениям. Одна строка на прогон, новые - в конец:

```
YYYY-MM-DD | <D> | <slug> | scan|new|answers|status | domain=#.. business=#.. system=#.. company=#.. | hyp: <гипотеза или -> | fish: +N new (b#..), M reused (b#..) | pattern: +N new (p#..), M reused | files: <пути от CT> | прим.: <если есть>
```

Для `status` поля тегов и рыбы - `-`, в `прим.` - стадия.

Для `scan` вместо `<slug>` - `-` (прогон не про одну вакансию), поля тегов, гипотезы и рыбы - `-`, в `прим.` - итог триажа: сколько карточек просмотрено, сколько прочитано, сколько в шортлисте, что синхронизировано с `applications.list`.

## audit/TLDR.md

Сводка на одну страницу. Автоматические разделы пересобираются целиком, «Заметки» только дописываются.

```md
# TL;DR

Обновлено: YYYY-MM-DD | прогонов в vacancy-history: N

## Направления
| | В работе | Архив | Ответили | Тишина / отказ | bullets | patterns |
| hh | .. |
| hirify | .. |
| linkedin | .. |

## Гипотезы
| Гипотеза | Направление | Откликов | Ответов | Вывод |
(из поля «Гипотеза» карточек и стадий в BOARD; вывод - только когда откликов 3+)

## Топ-теги
- домен / бизнес / система / компания: #тег xN ...

## Самые переиспользуемые записи
- <D> b#N (#теги) - Nx (slug, slug)

## Заметки
- YYYY-MM-DD - устойчивое наблюдение, решение пользователя, пробел
```
